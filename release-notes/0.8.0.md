Both networks run new contracts, which fix how they count the DOT that pays for cross-chain
settlement. Trading in the app, which is local, is unchanged.

- A market records an order's fee reserve in planck, the unit XCM moves DOT in. Until now it recorded
  `msg.value`, which counts in 18-decimal units (10^8 per planck on Paseo), and took fees from it in
  planck, so a refund sent 10^8 times the reserve and reverted.
- A cross-chain fee of 0 disables cross-chain orders, which revert with `CrossChainDisabled`; the
  factory refuses a fee of 1 planck, too small for a valid message. Both networks now set 0.1 PAS.
- The market creation deposit is in planck, as its name says.
- A settlement message the XCM precompile refuses to weigh now waits as a pending claim, as one it
  fails to execute does, and no longer reverts the order.

**For integrators:** `DLOBFactory`'s constructor takes a fourth argument, `nativeToEthRatio`:
10^(18 - the native token's decimals). Send `msg.value` in 18-decimal units as before; the fee, the
deposit, `getOrderFeeReserve`, `totalFeeReserveBalance` and `sweepOrphanedDot`'s amount are in planck.
